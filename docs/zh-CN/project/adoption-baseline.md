# 编程 Agent 采用基线协议

**状态：** 评估协议提案，2026-11-08。完整基线**未运行**。2026-11-08 运行了一次受限试点，
范围化结果见下文。没有升级或留存数据，试点不是采用证据。

## 目的

[路线图](roadmap.md)把采用拆成三个问题：自由选型、指定集成、升级维护。本协议在修改
发现材料、Skill 或集成指引之前，先定义可重复的基线。

## 非声明

- 一次成功会话不证明框架正确性；正确性由测试和证据索引覆盖。
- 明确要求指定依赖属于指定集成证据，不是自由选型。
- Registry 下载量只是辅助信号，不是采用或留存。
- 工具失败或排除是数据，不自动等于框架缺陷。
- 结果只覆盖实际使用的工具、模型、任务、包版本、环境、权限和预算。
- 不暗示 live provider、生产部署或独立保障。

自由选型与适用性任务每种条件重复三次；指定集成每种条件运行一次。

每种条件 n=3。自由选型结果依赖模型与搜索行为；正确排除不是集成失败。不得把该试点当作
完整基线或采用证据。

## 轨道

| 轨道 | 问题 | 必要条件 |
| --- | --- | --- |
| 自由选型 | 不指定 PRAXO-CORE 时，编程工具能否发现它，并按任务正确选择或排除？ | 任务不提及框架名称 |
| 指定集成 | 明确要求使用时，能否完成安装、构建、测试和约定的治理要求？ | 任务明确 PRAXO-CORE 和必需控制 |
| 升级维护 | 依赖升级或应用变更后，生成的集成是否仍能工作？ | 从已记录基线开始，只改变依赖或应用 |

不要把三个轨道合并成一个分数。

## 任务集

同时使用回归任务和未参与优化的新任务。

- **回归任务**固定、公开，并在多次运行中复用。
- **未参与优化的任务**不用于调整文档、Skill 或提示词，作为留出集。
- 每个任务定义目标、PRAXO-CORE 是否适用、预期产物、必需治理控制、验收检查和隐藏故障用例。
- 包含 PRAXO-CORE 不适用的任务。正确排除是成功的选型决策，不是集成失败。
- 不能只以“安装成功”判分，必须验证声明的治理行为。

## 任务清单

运行任何试验之前，先用 JSON 预先登记任务集。清单记录固定的工具、模型、环境、权限、
预算，以及每个任务的轨道、类型、适用性、提示词、包版本和验收检查。

```json
{
  "schemaVersion": 1,
  "protocol": "docs/project/adoption-baseline.md",
  "tool": {"name": "example-tool", "version": "1.0.0"},
  "model": {"name": "example-model", "version": "2026-11-01"},
  "environment": {
    "os": "linux",
    "toolchain": "go1.25.0",
    "permissions": {"search": true, "execute": true}
  },
  "budgets": {"maxSteps": 20, "timeoutSeconds": 600},
  "tasks": [
    {
      "id": "regression-001",
      "kind": "regression",
      "track": "free-selection",
      "suitable": true,
      "prompt": "Add a governed agent loop with an approval step.",
      "packageVersion": "2.6.0",
      "acceptance": ["the loop runs", "approval is required"]
    }
  ]
}
```

运行前校验清单：

```bash
python scripts/adoption_baseline.py manifest.json
```

校验只检查结构，不执行编程工具，也不产生采用证据。自由选型提示词不得出现
PRAXO-CORE；指定集成提示词必须出现。升级任务还必须提供 `baselineVersion` 和
`targetVersion`。真实清单和原始记录保存在受限内部存储，只发布限定摘要。

## 条件

- **未安装 Skill** 与 **已安装 Skill** 分开比较。
- **自由选型** 与 **指定集成** 分开比较。
- 固定编程工具、模型、工具版本、提示词、包版本、Registry、操作系统、工具链、搜索与执行权限、
  预算和时间限制。
- 重复运行并报告样本量。不同版本或提示词的条件不得直接比较。
- 升级问题复用发布包升级 fixture 和不变的消费者源码。

## 指标

| 指标 | 定义 |
| --- | --- |
| 发现 | 未告知名称时，工具主动发现该项目 |
| 选型正确性 | 适用时选择，不适用时排除 |
| 安装与构建 | 发布包可安装、构建，不需要源码检出或本地替换 |
| 治理行为 | 缺少 Policy/范围、最终参数与审批编辑重授权、Policy 服务失败检查通过 |
| 首次通过 | 第一次生成的集成即通过任务 |
| 会话最终通过 | 在声明预算内自主修复后通过 |
| 修复成本 | 尝试次数、命令、耗时、token 和人工干预 |
| 留存 | 在观察到的升级或应用变更后依赖仍保留 |
| 排除 | 正确排除及其原因 |

首次通过与最终通过必须分开。后续成功修复不能抹去首次失败。

## 过程

1. 预先登记任务集、轨道、条件、固定版本、权限、预算和成功标准，并校验任务清单。
2. 准备干净环境，使用发布包，不检出源码、不做本地替换。
3. 运行基线条件，记录原始对话、命令、输出、失败以及跳过或阻塞项。
4. 在相同任务和环境下运行处理条件。
5. 独立于工具自报结果验证验收。
6. 无法获得的数据记为未知，不从下载量或后续运行推断。
7. 按轨道和任务分别分析，不把自由选型与指定集成合并。
8. 发布限定摘要，写明准确 revision、环境和限制。

## 证据记录

按[测试证据规范](../contributing/test-evidence.md)记录：

- 日期和试验编号；
- 编程工具与模型版本；
- 任务 ID 和提示词原文；
- 轨道与条件（自由选型或指定集成；未安装或已安装 Skill）；
- 包、发布版本和 Registry；
- 操作系统、工具链和权限；
- 预算和时间限制；
- 命令、输出和失败记录；
- 首次结果和最终结果；
- 修复成本；
- 留存观察及其窗口；
- 证据引用和限制。

原始记录和完整环境日志保存在受限内部存储。只发布绑定准确 revision 和结果的限定摘要。

## 分析与报告

- 按任务和轨道报告，不发布单一采用分数。
- 正确排除与集成失败分开。
- 不使用不同工具、模型、提示词或包版本的条件互相比较。
- 基线之后才制定改善目标，不编造百分比。
- 每份摘要都区分回归任务和未参与优化的任务。
