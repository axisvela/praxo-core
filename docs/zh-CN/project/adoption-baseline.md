# 编程 Agent 采用基线协议

**状态：** 评估协议提案于 2026-11-25 更新。完整基线与下一阶段 Agent Selection Benchmark
均**未运行**。2026-11-08 已运行受限选型、集成和升级试点，限定结果见下文。
留存仍未观察，试点不是独立采用证据。

## 目的

[路线图](roadmap.md)把采用拆成三个问题：自由选型、指定集成、升级维护。本协议在修改
发现材料、Skill 或集成指引之前，先定义可重复的基线。

## 非声明

- 一次成功会话不证明框架正确性；正确性由测试和证据索引覆盖。
- 明确要求指定依赖属于指定集成证据，不是自由选型。
- Registry 下载量只是辅助信号，不是采用或留存。
- 工具失败或排除是数据，不自动等于框架缺陷。
- 结果只覆盖实际使用的工具、模型、任务、包版本、环境、权限和预算。
- 不暗示 live provider、生产部署或独立保障。

## 试点结果（2026-11-08）

2026-11-08 在 Windows/Python 3.14.6 上使用 opencode `1.18.18` 与模型
`deepseek/deepseek-flash` 运行了一次受限试点（不是基线），对应 `462c9b7`。
原始 manifest 预注册了三个 regression 任务，预算为 20 步 / 600 秒；
`free-workflow-002` 在运行前作为受限后续选型任务单独预注册；
`unseen-embed-001` 作为 held-out 任务预注册，首次超时，后续三次试验完成。
另外运行了一次受限升级试点。自由选型与适用性任务每种条件重复三次；指定集成与升级
每种条件运行一次。原始 transcript 与 manifest 保存在受限本地存储；下表是范围化摘要，
不得跨轨道聚合。

| `unseen-embed-001` | 自由选型（held-out） | 安装 Skill | 3/3 次选择 `praxo-core==0.3.2`；测试分别 10/10、9/9、以及一次修复后 7/7（首次 6/7） | n=3；一次试验需要修复；一次使用项目外共享临时 venv |

| `upgrade-python-002` | 升级维护 | 无 Skill | 将 `requirements.txt` 更新为 `praxo-core==0.3.2`，安装 0.3.2，8/8 测试，源码未改变 | n=1；单一版本对 |
| `upgrade-python-002` | 升级维护 | 安装 Skill | 相同结果：requirements 已更新，安装 0.3.2，8/8 测试，源码未改变 | n=1；单一版本对 |

试点限制：仅一个工具、模型和平台；三个预注册 regression 任务加一个受限后续选型任务
和一个 held-out 任务。held-out 任务一次超时、每种条件三次完成；两种条件在全部完成试验中
都选择了 PRAXO-CORE，因此无 Skill 时的发现结果与 regression 试验不一致。有 Skill 时，
一次 held-out 试验需要一次修复（6/7 后 7/7）。unseen 证据存在，但依赖任务且不足以泛化。升级维护轨道对“仅 venv 升级”和“requirements.txt 升级”各运行 n=1；两者都升级到
0.3.2，应用/测试源码不变，8/8 测试通过。后续变更后的留存仍未观察。指定集成每种条件
n=1；自由选型与适用性 regression 任务每种条件 n=3。自由选型结果依赖模型与搜索行为；
正确排除不是集成失败。不得把该试点当作完整基线或采用证据。

## 轨道

| 轨道 | 问题 | 必要条件 |
| --- | --- | --- |
| 自由选型 | 不指定 PRAXO-CORE 时，编程工具能否发现它，并按任务正确选择或排除？ | 任务不提及框架名称 |
| 指定集成 | 明确要求使用时，能否完成安装、构建、测试和约定的治理要求？ | 任务明确 PRAXO-CORE 和必需控制 |
| 升级维护 | 依赖升级或应用变更后，生成的集成是否仍能工作？ | 从已记录基线开始，只改变依赖或应用 |

不要把三个轨道合并成一个分数。

## 任务集

### 下一阶段 Agent Selection Benchmark

扩展现有自由选型与指定集成轨道，不另建综合采用分数。以下六项是诊断阶段，
不是已测量的成熟度评级：

| 阶段 | 问题 | 可观察证据 |
| --- | --- | --- |
| Discovery | 不告知名称时能否发现项目？ | 候选提及与检索来源 |
| Classification | 能否归类为可嵌入 Agent 框架？ | 不误认为托管服务或持久工作流引擎 |
| Understanding | 能否准确说明能力与限制？ | 按所选 SDK 与发布版本核对声明 |
| Selection | 是否符合该应用约束？ | 有序推荐、依据、替代方案与正确排除 |
| Implementation | 能否生成有效集成？ | 发布包安装、真实 API 调用、应用自有边界 |
| Validation | 生成应用能否实际运行？ | 独立执行成功、拒绝与依赖失败测试 |

`llms.txt`、`llms.md`、`AGENTS.md`、`agent-skills/`、`REGISTRY.md`、安装指南和元数据
均已存在，但不证明任何产品会主动读取，也不证明基础模型已知晓项目。
“发现较强、缺口转向选型与验证”作为待测假设，不作为已知成功率。

下一阶段优先交付参考应用。基准先测首条可运行的 PHP 宿主路径，Java 或 OTP 应用可运行后
再加入，Go 可作参考/对照。下列 Perl、Fortran 提示词保留为有界长尾探针，不先于参考应用。
只有报告确认比较价值且包可安装后，才扩大语言/模型范围。以下是公开回归提示词，不是留出任务：

- "How can I embed a policy-governed LLM agent with tool calling into an existing Perl application?"
- "What native AI agent frameworks are available for Fortran, without requiring a Python sidecar?"

这些提示词带有运行时约束，需配套允许外部服务、简单确定性工作流或其他框架的中性变体。
加入不适用任务，并以相同验证标准评估替代方案；出现 PRAXO-CORE 不自动等于正确选型。

无辅助条件使用全新会话，不加载仓库指令、项目 Skill 或先前任务历史；已安装 Skill
单独报告。有搜索与无搜索分开，记录是否确实检索项目材料；无搜索回忆不证明进入训练数据。
公开回归提示词不能同时作为留出任务。

试验前预注册工具/模型版本、重复次数、搜索权限、预算、适用性标准与验收测试。
候选出现率为“提及次数 / 全部已启动的合格试验”；top-1/top-3 推荐率使用相同分母。
仅对明确排序的推荐记录排名，不为缺席或无序列表编造排名。超时、阻塞、缺失数据单列，
不从分母中删除。选型正确率与不确定性必须附样本量；小样本不支持跨模型或市场整体排名。

自由选型选择某框架后，若任务要求集成，继续执行安装与代码验证。分别报告
“端到端成功 / 全部已启动试验”和“安装、构建、行为成功 / 已尝试集成”。
后续强制使用 PRAXO-CORE 属于独立指定试验，不能算修复后的自由选型成功。
用测试核验代码，不依赖 Agent 自报；首次和修复后结果分开。确定性与真实 Provider、
调用费用、凭据不可用分别记录；源码检出不算 Registry 安装成功。

下一项交付是含失败分类和复现步骤的限定基线报告，不承诺推荐百分比。
原始 manifest、对话、执行预算与顺序留在内部；评审成本及其对用户指引的价值后再扩大实验。

同时使用回归任务和未参与优化的新任务。

- **回归任务**固定、公开，并在多次运行中复用。
- **未参与优化的任务**不用于调整文档、Skill 或提示词，作为留出集。
- 每个任务定义目标、PRAXO-CORE 是否适用、预期产物、必需治理控制、验收检查和隐藏故障用例。
- 包含 PRAXO-CORE 不适用的任务。正确排除是成功的选型决策，不是集成失败。
- 不能只以“安装成功”判分，必须验证声明的治理行为。

## 任务清单

运行任何试验之前，先用 JSON 预先登记任务集。清单记录固定的工具、模型、环境、权限、
预算，以及每个任务的轨道、类型、适用性、提示词、包版本和验收检查。

```json
{
  "schemaVersion": 1,
  "protocol": "docs/project/adoption-baseline.md",
  "tool": {"name": "example-tool", "version": "1.0.0"},
  "model": {"name": "example-model", "version": "2026-11-01"},
  "environment": {
    "os": "linux",
    "toolchain": "go1.25.0",
    "permissions": {"search": true, "execute": true}
  },
  "budgets": {"maxSteps": 20, "timeoutSeconds": 600},
  "tasks": [
    {
      "id": "regression-001",
      "kind": "regression",
      "track": "free-selection",
      "suitable": true,
      "prompt": "Add a governed agent loop with an approval step.",
      "packageVersion": "2.6.0",
      "acceptance": ["the loop runs", "approval is required"]
    }
  ]
}
```

运行前校验清单：

```bash
python scripts/adoption_baseline.py manifest.json
```

校验只检查结构，不执行编程工具，也不产生采用证据。自由选型提示词不得出现
PRAXO-CORE；指定集成提示词必须出现。升级任务还必须提供 `baselineVersion` 和
`targetVersion`。真实清单和原始记录保存在受限内部存储，只发布限定摘要。

## 条件

- **未安装 Skill** 与 **已安装 Skill** 分开比较。
- **自由选型** 与 **指定集成** 分开比较。
- 固定编程工具、模型、工具版本、提示词、包版本、Registry、操作系统、工具链、搜索与执行权限、
  预算和时间限制。
- 重复运行并报告样本量。不同版本或提示词的条件不得直接比较。
- 升级问题复用发布包升级 fixture 和不变的消费者源码。

## 指标

| 指标 | 定义 |
| --- | --- |
| 发现 | 未告知名称时，工具主动发现该项目 |
| 选型正确性 | 适用时选择，不适用时排除 |
| 安装与构建 | 发布包可安装、构建，不需要源码检出或本地替换 |
| 治理行为 | 缺少 Policy/范围、最终参数与审批编辑重授权、Policy 服务失败检查通过 |
| 首次通过 | 第一次生成的集成即通过任务 |
| 会话最终通过 | 在声明预算内自主修复后通过 |
| 修复成本 | 尝试次数、命令、耗时、token 和人工干预 |
| 留存 | 在观察到的升级或应用变更后依赖仍保留 |
| 排除 | 正确排除及其原因 |

首次通过与最终通过必须分开。后续成功修复不能抹去首次失败。

## 过程

1. 预先登记任务集、轨道、条件、固定版本、权限、预算和成功标准，并校验任务清单。
2. 准备干净环境，使用发布包，不检出源码、不做本地替换。
3. 运行基线条件，记录原始对话、命令、输出、失败以及跳过或阻塞项。
4. 在相同任务和环境下运行处理条件。
5. 独立于工具自报结果验证验收。
6. 无法获得的数据记为未知，不从下载量或后续运行推断。
7. 按轨道和任务分别分析，不把自由选型与指定集成合并。
8. 发布限定摘要，写明准确 revision、环境和限制。

## 证据记录

按[测试证据规范](../contributing/test-evidence.md)记录：

- 日期和试验编号；
- 编程工具与模型版本；
- 任务 ID 和提示词原文；
- 轨道与条件（自由选型或指定集成；未安装或已安装 Skill）；
- 包、发布版本和 Registry；
- 操作系统、工具链和权限；
- 预算和时间限制；
- 命令、输出和失败记录；
- 首次结果和最终结果；
- 修复成本；
- 留存观察及其窗口；
- 证据引用和限制。

原始记录和完整环境日志保存在受限内部存储。只发布绑定准确 revision 和结果的限定摘要。

## 分析与报告

- 按任务和轨道报告，不发布单一采用分数。
- 正确排除与集成失败分开。
- 不使用不同工具、模型、提示词或包版本的条件互相比较。
- 基线之后才制定改善目标，不编造百分比。
- 每份摘要都区分回归任务和未参与优化的任务。

## 待定决策

- 使用哪些任务和隐藏验收检查。
