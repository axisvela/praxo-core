# Embodied Integration Profile

**状态：2026-11-06 设计提案；消费者试点未开始。** 不新增具身运行时、中间件适配器、Core API
或安全保证。本文细化[执行层次](execution-profiles.md)与
[Governed Execution Profile](governed-execution.md)，不代替规范性 Wire spec。

## 前置条件

试点需一个明确消费者、一个中间件、一个有边界的仿真任务、执行权威、观测源和效果验证规则。
本设计未选定这些条件。不在缺少消费者证据时并行开发 ROS 2、Dora、Zenoh 适配器，
也不要求使用 AxisVela 产品。

消费者必须明确治理要求由谁执行；“实验”标签不能免除授权或弱化失败处理。开发 fixture 不是安全控制。

## 责任边界

| 组件 | 责任 |
| --- | --- |
| Core | 局部 Run、已配置 Policy/HITL、工具调用、事件、取消与 Checkpoint 契约 |
| 消费者适配器 | 翻译操作与观测、关联 ID、限制输入与资源范围、保留不确定结果 |
| 执行权威 | 接受/拒绝命令，拥有权威远程状态、去重和取消确认 |
| 观测/验证者 | 提供带时间戳的观测，检查新鲜度，独立于成功响应验证声明效果 |
| 按需接入的工作流/协调服务 | 持久恢复、任务协调、lease 与 fencing |
| 部署安全系统 | 急停、联锁、实时控制、硬件限制和批准的安全状态行为 |

局部 Run、协调 Task、持久 Process、机器人 Mission 的 ID 与权威分别保留；这些是概念映射，
不是新增 Core 必需字段。Core run 完成不能升级为 Mission 完成。

## 验收提案

治理要求全部适用；以下只增加领域要求。编号是文档引用，不是 Wire code 或新增状态枚举。

| ID | 要求 | 负向或故障验收 |
| --- | --- | --- |
| E1 | 授权最终目标、动作和参数 | 缺失身份、目标/范围不匹配或审批编辑后不满足授权，阻止提交 |
| E2 | 分开接受、完成与效果验证 | 接受命令或工具返回成功，单独都不能证明物理效果 |
| E3 | 限制观测新鲜度 | 缺失、过期、乱序观测阻止依赖它的新动作；声明时钟假设和有效期限 |
| E4 | 确认远程取消 | 本地 Run 取消不报告远程停止；没有确认则保留未知/待确认 |
| E5 | 处理重复和不确定提交 | 稳定操作键绑定载荷；响应丢失/重连先查权威状态，再决定重试 |
| E6 | 必需安全依赖失败关闭 | Policy、观测、安全服务丢失时阻止新的依赖动作，并按消费者规则升级处理 |
| E7 | 对恢复和并发所有权执行 fencing | 过期 worker/lease 不得发起新效果；恢复 Checkpoint 不重建执行权威 |
| E8 | 保留关联证据 | 记录命令、权威响应、观测、取消和 verifier 结果且不泄露秘密；证据故障与效果状态分开 |

消费者定义新鲜度阈值、时钟域、超时、所有权与取消协议，本设计不虚构通用安全默认值。
对已执行的动作，“失败关闭”不意味着 Core 可以停机：受控停止/升级处理与确认由部署安全权威负责。
不得把依赖丢失报告为已确认安全状态。

## 证据与晋级

声明实验性实现前，记录明确消费者与中间件、准确 Core/adapter/runtime 版本、仿真环境和任务、
执行组件、E1-E8 各项测试结果及未支持行为。需测试观测过期、断连、响应丢失、重复提交、取消未确认、
过期所有权与必需安全服务故障。

[长时操作配方](../guides/long-running-operations.md)提供响应丢失、状态恢复、取消和 fencing 的
软件 fixture，但不提供观测、中间件、生产 lease 或具身消费者；配方测试通过不满足本 Profile。

按[测试分类](../project/test-taxonomy.md)区分确定性 fixture、端到端仿真、硬件试验和生产观察。
仿真不是硬件或生产证据。每项限定结果应附限制和剩余风险；本文不声明完整 Profile 已通过。

## 非目标

Core 不是机器人平台、运动规划器、硬件驱动、认证安全控制器、分布式工作流引擎或实时运行时。
本 Profile 不提供急停实现、外部事务原子性或通用 exactly-once。共享 API/Wire 变化仍需正常
兼容性、spec、parity 流程，不能因属于 Profile 而豁免。
