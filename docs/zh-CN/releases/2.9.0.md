# PRAXO-CORE 2.9.0

**发布日期：** 2026-11-16

PRAXO-CORE 2.9.0 是次版本发布，修正 Go 参考实现的记忆召回信任边界。该版本改变模型请求行为，但不新增导出的 `pkg/...` API 或共享 Wire 形状。其他语言实现和可选适配器独立版本化；本版本不宣称它们具有相同的记忆行为。

## 重点

- **召回内容是可信度较低的 user 数据。** 召回记录不再作为 system 消息注入，而是放入带 frame/source 标签的 user 数据块。
- **记忆元数据。** assistant 写入的记忆记录带 `source` 与 `trust` 元数据；缺少来源时显示 `unknown`，存储中的 trust 标签不能把召回内容提升为 system 权威。
- **两轮回归。** 测试覆盖 assistant 输出、应用保存的工具结果和外部写入的两轮路径；被拒绝的工具调用仍产生零效果。
- **无 API 或 Wire 变更。** `api/2.9.0.txt` 与 `api/2.8.0.txt` 相同。
- **Bridge 范围仍未知。** Bridge 可能调用 Go，但本版本不确认 Bridge 是否暴露自动记忆召回。

## 升级

```bash
go get github.com/axisvela/praxo-core/v2@v2.9.0
```

导出的 `pkg/...` API 无需源码迁移。使用召回的消费者应复核模型请求快照和任何依赖 system 角色的自定义压缩。历史记录无需重写。可信应用指令应与召回内容分离，不应恢复模型或外部文本的 system 权威。

该修复移除一条角色抬升路径，但不防止所有提示注入。需要更严格边界的应用应自行组装上下文或关闭自动召回。

## 验证

- Go tests、vet、build 和两轮记忆定向回归通过。
- `pkg/agent` race 检查通过。
- `api/2.9.0.txt` 与 `2.8.0` 记录相同的声明基线。
- 发布工作流要求同一提交的 CI 和文档运行成功后才发布。
- `scripts/check_release_metadata.py` 校验版本、快照、发布说明、changelog、索引、模块路径和编程 Agent 包映射。

## 限制

- 本版本不宣称 Bridge 或其他 SDK 具有相同召回行为。跨 SDK 审计未发现其他 Agent 主路径的自动召回，但 Memory Store API 是独立能力。
- 记忆召回不是身份提供商、策略决策服务或通用提示注入防御。
- 发布后的干净外部安装和消费者重跑单独记录；本页不把源码测试当作 Registry 证据。
