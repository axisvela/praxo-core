# PRAXO-CORE 2.6.0

**发布日期：** 2026-11-07

PRAXO-CORE 2.6.0 是次版本发布。导出的 `pkg/...` 声明与 `2.5.2` 相同；
`api/2.6.0.txt` 记录同一声明基线。本次发布增加了经过验证的消费者集成材料与
Execution Correctness 证据/runner，并改变了工具批处理出错后 Go 回调/流的可观察顺序。

## 重点

- **工具结果通知。** Go `pkg/agent` 在工具批处理报告首个工具错误后，仍会为每个已执行的
  工具继续发送 task-end 与 `OnToolResult` 通知，然后返回首个工具错误。这改变了工具错误后
  回调与流的可观察顺序。Checkpoint 状态仍不证明外部效果已提交。
- **Execution Correctness Suite。** 公共 EC 证据索引把 EC-01 至 EC-14 映射到 Core 与具名
  产品。严格的 EC-D runner 选择精确的 Go 测试并写入可复现的 JSON/Markdown 报告。基线 scope
  （`27/27`）覆盖 EC-01/03/04/06/08/10/14 的局部机制；独立 containment scope（`5/5`）覆盖
  EC-11 的路径、VFS 与 WASM 限制控制。scope 通过不等于完整 EC、EC-I、EC-O 或 Profile 验收。
- **独立消费者路径。** Go、Python、TypeScript 与 Java Starter 使用已发布包、确定性模型、
  显式工具范围与允许/拒绝检查，无需检出源码、本地替换、API Key 或外部模型服务。这是集成
  证据，不是采用证据。
- **治理验收。** 四种 Starter 语言增加可由消费者运行的负向检查：缺少 Policy/范围、最终参数
  与审批编辑再授权、Policy 服务失败。这些是应用层检查，不是通用 Core 安全 Profile。
- **配方与 Agent 材料。** 提供经过验证的 Go 身份/策略配方、Go 长时操作配方、编程 Agent 集成
  契约与版本校验包映射，以及工具中立的 Skill 模板。发布时 Skill 安装与发现尚未验证；
  2026-11-08 的 Claude Code `2.1.196`（结构发现）与 opencode `1.18.18`
  （结构发现加使用已发布包的确定性 allow/deny 任务）本地检查已记录在验证证据中。
- **Wire 描述。** 记录 Tool、Model、Checkpoint Wire 描述与共享 Wire 变更分类，不扩大 Go API。

## 升级

```bash
go get github.com/axisvela/praxo-core/v2@v2.6.0
```

导出的 `pkg/...` API 不需要源码迁移。若消费者假设首个工具错误后不会再收到 task-end 或
`OnToolResult` 通知，必须更新处理器以容忍后续成功结果。

## 验证

- 发布提交要求根 Go 测试、vet、build、静态分析、漏洞扫描、API 快照与 fuzz 检查通过。
- 本地 EC-D 基线报告 `27/27` selected selectors，containment scope 报告 `5/5`，均为
  `scope-passed`。
- CI 要求 Go、Python、TypeScript 与 Java 消费者安装、构建与确定性允许/拒绝检查通过。
- `api/2.6.0.txt` 与 `api/2.5.2.txt` 相同。

## 限制

- 完整 EC-01 至 EC-14 验收、EC-I、EC-O 与所有 Profile 验收仍未运行或属外部。
- 采用、留存与编程 Agent 选型实验尚未运行。
- 真实 sandbox 隔离、live provider、外部身份/策略服务与生产部署证据仍不在 Core 内。
- 源码标签不会把本地证据变成生产验收。
