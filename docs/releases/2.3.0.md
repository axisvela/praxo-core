# PRAXO-CORE 2.3.0

**Released:** 2026-10-23

PRAXO-CORE 2.3.0 focuses on execution correctness, lifecycle control, and
bounded concurrency. It adds two exported methods to the frozen `pkg/...`
surface and keeps all other interfaces unchanged.

## Highlights

- **Subagent lifecycle:** `SubagentManager.Wait` blocks on completion events and
  `SubagentManager.Prune` removes stale terminal tasks. `Cancel` no longer
  overwrites terminal state, and `Update` requires a running task.
- **Real parallel composition:** `flow.Parallel` executes runnables
  concurrently, preserves output order, and returns the first error by index.
- **Bounded multi-agent supervision:** `adapters/multiagent` waits on completion
  events instead of polling, and `MaxConcurrency` caps parallel workers.
- **Streaming usage:** `adapters/openaicompat` can request
  `stream_options.include_usage` and maps streamed token usage into
  `model.Usage`.
- **Memory store:** generated IDs are collision-resistant, search text is
  precomputed on `Put`, and the zero value is usable.
- **MCP pagination:** resource and prompt listings reject repeated cursors;
  multi-page listing is tested.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.3.0
```

No source changes are required for consumers of 2.2.0. `api/2.3.0.txt` differs
from `api/2.2.0.txt` only by `SubagentManager.Wait` and
`SubagentManager.Prune`.

## Optional Modules

- New: `adapters/multiagent/v0.2.0`
- New: `adapters/mcp/v0.3.0`
- Unchanged: `adapters/otel/v0.2.0`, `adapters/anthropic/v0.1.0`,
  `adapters/gemini/v0.1.0`, `adapters/harmovela/v0.1.0`,
  `adapters/a2a/v0.1.0`

## Validation

- API diff from 2.2.0: two additive methods, no removals or signature changes
- CI: test, vet, build, race, fuzz, staticcheck, govulncheck, benchmarks
- Docs site built with `mkdocs build --strict`
- Published-module consumer check updated to the 2.3.0 tags

## Limits

- Adapter integration tests are deterministic protocol tests; they do not prove
  live-service or production validation.
- A2A covers an in-process HTTP JSON-RPC round trip, not an external peer or
  gRPC interoperability.
- Multi-agent support remains subagent delegation plus an optional supervisor
  module, not a durable graph runtime. Durable graph execution belongs to
  RHEOVELA.
