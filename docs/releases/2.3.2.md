# PRAXO-CORE 2.3.2

**Released:** 2026-10-23

PRAXO-CORE 2.3.2 is a patch release that corrects Gemini streaming candidate
selection and hardens provider and security recipes. It adds no exported
`pkg/...` declarations.

## Highlights

- **Gemini streaming:** the adapter now consumes only the first candidate in
  each streamed response, matching non-streaming behavior and preventing text
  or tool calls from alternate candidates being mixed into the result.
- **Provider recipes:** MCP registration uses `NewTools` to preserve input
  schemas; policy and egress recipes document static routes and credential
  handling; event recipes document data hygiene.
- **Security examples:** the sandbox recipe authorizes the same command that it
  executes and clearly states that policy-gated host execution is not OS-level
  isolation. The reference workspace policy allows only `model.generate` and
  `fs.*` calls.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.3.2
```

No source changes are required for consumers of 2.3.1. `api/2.3.2.txt` is
identical to `api/2.3.1.txt`.

## Optional Modules

`adapters/gemini/v0.1.1` includes the Gemini streaming fix. Other published
optional module tags are unchanged.

## Validation

- Core, adapter, ecosystem SDK, and example test/vet/build suites pass.
- Docs build with `mkdocs build --strict`.
- Staticcheck and govulncheck pass.
- Linux CI remains the race-detector gate.

## Limits

- Adapter tests are deterministic protocol tests; they do not prove live
  service or production validation.
- Real provider validation requires opt-in credentials and separate billing,
  rate-limit, and secrets controls.
- A2A covers in-process JSON-RPC and gRPC round trips, not an external peer.
