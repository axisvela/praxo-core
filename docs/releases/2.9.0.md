# PRAXO-CORE 2.9.0

**Released:** 2026-11-16

PRAXO-CORE 2.9.0 is a minor release correcting the Go reference agent's memory
recall trust boundary. It changes model-request behavior but adds no exported
`pkg/...` API or shared wire shape. Other language implementations and optional
adapters are versioned independently; this release does not claim the same
memory behavior in them.

## Highlights

- **Recall is untrusted user data.** Recalled records are no longer injected as
  system messages. They are placed in a user data block with frame and source
  labels when available.
- **Memory metadata.** Assistant-written memory records carry `source` and
  `trust` metadata. Missing source metadata is shown as `unknown`, and a stored
  trust label cannot elevate recalled content to system authority.
- **Two-run regressions.** Tests cover assistant output, application-stored tool
  results, and external writes across two runs. A denied tool call still has
  zero effects.
- **No API or wire change.** `api/2.9.0.txt` is identical to `api/2.8.0.txt`.
- **Bridge scope remains unknown.** The bridge may call Go, but this release
  does not establish whether a bridge exposes automatic memory recall.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.9.0
```

No source migration is required for the exported `pkg/...` API. Applications
using recall should review model-request snapshots and any custom compaction
that depended on the system role. Stored records need no rewrite. Keep trusted
application instructions separate from recalled content and do not restore
system authority for model or external text.

This change removes a role-elevation path; it does not prevent all prompt
injection. Applications that require a stricter boundary should assemble
context themselves or disable automatic recall.

## Validation

Local release validation completed 2026-11-16: Go tests, vet, build, race,
staticcheck, and govulncheck; strict documentation build; API snapshot and
release-metadata checks.

- Go tests, vet, build, and the targeted two-run memory regressions pass.
- `pkg/agent` race checks pass.
- `api/2.9.0.txt` records the same declaration baseline as `2.8.0`.
- The release workflow requires same-commit CI and documentation runs before
  publication.
- `scripts/check_release_metadata.py` checks the version, snapshot, release
  notes, changelog, indexes, module path, and coding-agent package map.

## Limits

- The release does not claim that Bridge or any other SDK has the same recall
  behavior. The cross-SDK audit found no automatic recall in other agent main
  paths, but Memory Store APIs are separate capabilities.
- Memory recall is not an identity provider, policy decision service, or
  general prompt-injection defense.
- A clean external install and consumer rerun are recorded separately after
  publication; this page does not turn source tests into registry evidence.
