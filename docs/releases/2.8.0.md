# PRAXO-CORE 2.8.0

**Released:** 2026-11-14

PRAXO-CORE 2.8.0 is a minor release. It adds explicit safe-default options to
the Go reference agent and expands the runnable governance examples. The
exported `pkg/...` API gains two `agent.Options` fields; existing callers do not
need source changes.

## Highlights

- **Safe defaults.** `agent.Options.RequirePolicy` rejects construction when no
  `Policy` is configured. `RequireToolScope` rejects construction when
  `AllowedTools` is empty. Both are opt-in and default to `false`.
- **HITL example.** `examples/hitl` approves a write, then edits it and verifies
  final-argument reauthorization blocks the effect.
- **Multi-turn checkpoint example.** `examples/session-checkpoint` saves,
  reloads, and continues a conversation across two agent runs.
- **Parameterized live tool.** The live-model examples use `get_time(zone)` with
  a small JSON Schema so real models receive the tool parameter contract.
- **Go mirror.** The mirror sync now supports `axisvela/praxo-core-go` with the
  root Go module, examples, API snapshots, and `spec/`.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.8.0
```

Existing callers do not need source changes. The new fields are opt-in; an
application that does not set them keeps the previous behavior.

## Validation

- Root Go tests, vet, build, race, API snapshot, and fuzz checks are required for
  the release commit.
- `api/2.8.0.txt` records the new `RequirePolicy` and `RequireToolScope` fields.
- HITL and session-checkpoint examples are covered by their tests.
- The mirror sync and strict documentation build are required.

## Limits

- Safe defaults are construction-time guards. They do not authenticate identity,
  validate provider behavior, or enforce effects at the application boundary.
- A checkpoint is a recovery hint, not a transaction or an exactly-once
  guarantee.
- Go tool invocation already accepts `context.Context`; non-Go cancellation
  APIs remain future work.
