# PRAXO-CORE 2.6.0

**Released:** 2026-11-07

PRAXO-CORE 2.6.0 is a minor release. Exported `pkg/...` declarations are
identical to `2.5.2`; `api/2.6.0.txt` records the same declaration baseline. The
release adds verified consumer integration materials and the Execution
Correctness evidence/runner, and changes observable Go callback/stream ordering
after a tool batch error.

## Highlights

- **Tool outcome notification.** Go `pkg/agent` now continues task-end and
  `OnToolResult` notifications for every executed tool after a tool batch
  reports its first tool error, then returns that first error. This changes
  observable callback and stream ordering after a tool error. Checkpoint state
  still does not prove external effect commit.
- **Execution Correctness Suite.** A public EC evidence index maps EC-01 through
  EC-14 across Core and named products. The strict EC-D runner selects exact Go
  tests and writes reproducible JSON/Markdown reports. The baseline scope
  (`27/27`) covers EC-01/03/04/06/08/10/14 local mechanics; a separate
  containment scope (`5/5`) covers EC-11 path, VFS, and WASM limit controls. A
  scope pass is not full EC, EC-I, EC-O, or Profile acceptance.
- **Independent consumer path.** Go, Python, TypeScript, and Java starters use
  published packages, deterministic models, explicit tool scope, and
  allow/deny checks without a source checkout, local replacement, API key, or
  external model service. This is integration evidence, not adoption evidence.
- **Governed acceptance.** The four starter languages add consumer-runnable
  negative checks for missing policy/scope, final-argument and approval-edit
  reauthorization, and policy-service failure. These are application-level
  checks, not a general Core security profile.
- **Recipes and agent materials.** A verified Go identity/policy recipe, a Go
  long-running operation recipe, a coding-agent integration contract and
  version-checked package map, and a tool-neutral skill template are available.
  Skill installation and discovery were unverified at release time; a
  post-release local structural check for Claude Code `2.1.196` on 2026-11-08 is
  recorded in the verification evidence.
- **Wire descriptions.** Tool, model, and checkpoint wire descriptions and the
  shared-wire change classification are documented without widening the Go API.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.6.0
```

No source migration is required for the exported `pkg/...` API. Consumers that
assume no further task-end or `OnToolResult` notifications after the first tool
error must update handlers to tolerate later successful outcomes.

## Validation

- Root Go tests, vet, build, static analysis, vulnerability scan, API snapshot,
  and fuzz checks are required for the release commit.
- The local EC-D baseline reports `27/27` selected selectors and the containment
  scope reports `5/5`, both `scope-passed`.
- Go, Python, TypeScript, and Java consumer installation, build, and
  deterministic allow/deny checks are required in CI.
- `api/2.6.0.txt` is identical to `api/2.5.2.txt`.

## Limits

- Full EC-01 through EC-14 acceptance, EC-I, EC-O, and all Profile acceptance
  remain not-run or external.
- Adoption, retention, and coding-agent selection experiments have not run.
- Real sandbox isolation, live providers, external identity/policy services,
  and production deployment evidence remain outside Core.
- A source tag does not turn local evidence into production acceptance.
