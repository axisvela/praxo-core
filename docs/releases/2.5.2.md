# PRAXO-CORE 2.5.2

**Released:** 2026-10-30

PRAXO-CORE 2.5.2 is a security and behavior patch release. Exported `pkg/...`
declarations are identical to `2.5.1`; `api/2.5.2.txt` is intentionally the same
declaration baseline. The local VFS now performs actual file operations through
rooted handles after path authorization, and rejects absolute symlinks.

## Highlights

- **Rooted local VFS.** `pkg/vfs/localfs` uses `os.Root` for reads, writes,
  stats, listings, deletes, globs, and Grep file access after
  `policy.PathChecker` authorization. A symlink swapped after the check cannot
  redirect the actual operation outside the workspace root.
- **Symlink behavior change.** Absolute symlinks are now rejected by the local
  VFS. Workspace symlinks must use relative targets. This is a deliberate
  security exception documented under [Limits](#limits).
- **Governed workspace reference.** Required controls, final-argument
  authorization, single-use approvals, post-approval edit rejection, queued
  revocation, and masked tool errors have deterministic fixtures.
- **Context trust reference.** The opt-in example separates deployment
  instructions, digest-bound approved skills, untrusted memory/tool/summary
  data, and text restore without changing ordinary agent defaults.
- **OpenTelemetry example.** A runnable in-memory exporter demonstrates event
  spans and an allowlist that excludes tool arguments/results.
- **Verification evidence index.** Public evidence now states claim levels and
  limits for Core, containment, adapters, A2A/IAM contracts, integration
  recovery, and product effect ledgers.
- **CI and contract governance.** A verbose Linux containment job runs path,
  process, and WASM controls; language parity documentation now separates
  contract conformance, feature coverage, and operational evidence.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.5.2
```

No source migration is required for the exported `pkg/...` API. If a workspace
contains absolute symlinks, replace them with relative targets before upgrading,
or keep using `2.5.1` until the workspace is migrated.

## Validation

- Root Go tests, vet, build, API snapshot, race, fuzz, and module-security checks
  are required for the release commit.
- `api/2.5.2.txt` is identical to `api/2.5.1.txt`.
- Linux containment CI runs the symlink cases with verbose output. Windows hosts
  without symlink privilege report those cases as skipped.
- The public verification evidence index records the local integration recovery
  result and its limits.

## Limits

- `policy.PathChecker` decisions remain check-then-use outside `localfs`; callers
  still need OS-level confinement where their threat model requires it.
- Windows symlink behavior is not verified on hosts that cannot create
  symlinks.
- Linux cgroup v2 containment, deterministic WASM fuel, live workspace-provider
  verification, independent security review, and production readiness remain
  open.
- The local integration recovery run is loopback/local-PostgreSQL evidence, not
  a deployment, network-partition, concurrent-load, or production test.
- Absolute-symlink rejection is a security exception to the usual patch
  compatibility rule. Release review must retain this note and the affected
  behavior.
