# PRAXO-CORE 2.7.0

**Released:** 2026-11-09

PRAXO-CORE 2.7.0 is a minor release. Exported `pkg/...` declarations are
identical to `2.6.0`; `api/2.7.0.txt` records the same declaration baseline. The
release concentrates on runnable long-running operation and integration recipes,
published-package upgrade checks, and adoption/embodied evidence updates. It adds
no new `pkg/...` API.

## Highlights

- **Long-running operations.** The Go long-running recipe now injects
  deterministic failures before and after the rename boundary, rejects valid
  uncommitted temp state, and fails closed on corrupt committed state. Its fencing
  fixture models lease expiry, renewal, and revocation across restart, and a
  boundary test records lost updates from concurrent writers.
- **Standalone service and verifier.** The recipe builds a standalone service
  with health/readiness endpoints, bearer auth, optional TLS, graceful shutdown,
  basic request/error/operation metrics, environment-based configuration, and
  file-based token/secret rotation without restart. A separate verifier binary
  keeps its own token and signing secret.
- **Lease backends and recovery.** Mutations can use a file, SQLite, or Postgres
  lease with reload-modify-save under the lease. Process-level crash tests cover
  the commit boundary, and a gated 100-submission load/fault test plus a
  fresh-checkout reproduction script exercise acknowledged-operation recovery.
- **Integration recipes.** Adapter conformance, retry safety, event sinks,
  context budgets, checkpoint storage, structured output, VFS containment,
  provider fallback, plugin lifecycle, multi-agent delegation, streaming, and the
  workspace session contract have offline, runnable recipes.
- **Published-package upgrades.** Python `0.2.4` -> `0.3.0`, TypeScript
  `0.1.5` -> `0.2.0`, and Java `0.3.0` -> `0.4.0` fixtures install the historical
  package, upgrade the unchanged consumer, and rerun the starter/governed suite.
- **Adoption and embodied evidence.** Documentation records a bounded opencode
  adoption pilot, Claude Code structural discovery, and AKROVELA's product-owned
  adapter and deterministic P1 slice, while keeping the full baseline and E1-E8
  pilot explicitly open.

## Upgrade

```bash
go get github.com/axisvela/praxo-core/v2@v2.7.0
```

No source migration is required for the exported `pkg/...` API. `api/2.7.0.txt`
is identical to `api/2.6.0.txt`.

## Validation

- Root Go tests, vet, build, static analysis, vulnerability scan, API snapshot,
  and fuzz checks are required for the release commit.
- `scripts/check_release_metadata.py` checks `VERSION`, the API snapshot, both
  release-note pages, the changelog, both release indexes, the Go module major,
  and the coding-agent package map.
- Consumer and recipe checks install published packages and run deterministic
  allow/deny, governed, and long-running tests. Postgres lease tests are gated by
  `PRAXO_POSTGRES_DSN`.

## Limits

- The long-running work is L4 application-recipe evidence, not a production
  deployment, Core capability claim, or exactly-once guarantee.
- Live Postgres verification is still open: a local attempt on 2026-11-09 with
  PostgreSQL 18.1 on Windows did not complete (server exited with `0xC0000142`).
- OS-level power-loss proof, production lease coordination, a trusted clock, and
  live collector/alerting remain unverified.
- The adoption baseline is incomplete, retention after a later change is
  unobserved, and Codex/Copilot remain unverified.
- Embodied simulation, independent observations/verifier, ROS 2 execution,
  hardware effects, and E1-E8 pilot evidence remain open.
- A source tag does not turn local evidence into production acceptance.
